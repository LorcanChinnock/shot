# Website and user guide

Read this before changing `site/` or the user guide.

- `site/` is the Astro marketing site, built and deployed by Cloudflare Workers Builds (see `site/README.md`).
- The site's look follows the redesign's Website boards, whose values are in [the redesign spec](../redesign/spec.md) under Website values. [`site/DESIGN.md`](../../site/DESIGN.md) says how the site uses them, and the tokens and every shared component (`.button`, `.card`, `.ink-card`, `.panel.sand` and the rest) are classes in `site/src/styles/global.css`, so a page needs no CSS of its own.
- The tokens follow the app's light colours: a warm off-white page (`--bg`), white cards (`--surface`), near-black ink (`--ink`, `--line`) and yellow as the only accent (`--accent`, with `--on-accent` text). Red (`--record`, `--red-text`) is for Shot's own marks, such as the numbered badges. The five pastels (`--sand`, `--lilac`, `--sky-panel`, `--blush`, `--sage`) sit behind product shots only. Dark mode follows the visitor's system and uses the app's dark neutrals, with the pastels mixed into the card colour. Sticky notes (`--note`), callouts and the changelog's scope tags (`--tag-capture` and the others) keep their light colours in dark.
- One ink control per section, as in the app: the 2px outline, the 4px drop and the yellow go on the action you'd take next, and everything else is a quiet card or a secondary button. `scripts/lint.sh` rejects a card with one thick coloured edge.
- The social cards (`npm run og`, `site/scripts/og.mjs`) reuse `global.css` and `HeroStage.astro`. Their drawn scenes' bright fills (`--og-pink`, `--og-mint` and the rest) are defined in `og.mjs`, since the site itself keeps to its pastels.
- Motion is CSS only, using the spec's tokens (`--press`, `--pop`, `--sweep`, `--draw`, `--hover-ease`). All of it sits behind `prefers-reduced-motion: no-preference`, so Reduce Motion shows the page still. Give `animation-timeline` and `animation-range` a rule of their own, more specific than the one with the `animation` shorthand: in the same rule the minifier folds them into the shorthand, which can't hold them, and browsers drop it, which is why `.reveal` and `.pop.on-view` never moved before #1280. The only scripts are the copy buttons, the guide's search, the loops' play and pause, the "On this page" marker and closing the phone menu with Escape.
- The user guide lives in `site/src/guide/`, one Markdown file per page at `/docs/<slug>/`, in file name order. Each file's front matter gives its `title`, a one-line `summary` and its `group`. The groups, with each one's marker colour and the pastel behind its screenshots, are in `site/src/lib/guide-files.ts`.
- A page's address comes from its title, so when you rename a page, add its old slug to an `aliases` list in its front matter and the build redirects the old address to it.
- Write pages as tasks, in second person: numbered steps, `<kbd>⌘⇧4</kbd>` for keys, and `> [!TIP]`, `> [!NOTE]` or `> [!WARNING]` callouts. The build turns steps into numbered cards, a Tip into a sticky note and a screenshot on its own line into a shot on its group's pastel panel.
- Link to another page's section with just its id, `(#id)`, and the build points it at the right page.
- A new file becomes a new page, and Pagefind indexes it for the guide's search after the build, so search works under `npm run preview` but not `npm run dev`. The changelog page and its feed are built from `CHANGELOG.md` by `site/src/lib/changelog.ts`. release-please ignores `site/`.
