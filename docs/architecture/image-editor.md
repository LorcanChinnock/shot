# Image editor

Read this before changing annotations, their rendering or the editor's undo.

- `EditorDocument` / `Annotation` (ShotCore) is the model.
- `AnnotationRenderer` is shared by the on-screen canvas, flattened export, and the video compositors (`ProjectCompositor` via `AnnotationFrame`/`RenderCache`), so a rendering change affects them all.
- With a drawing tool, the mark just drawn stays selected so the style bar can restyle it. With the tools whose `EditorTool.showsHoverHandles` is true (arrow, line, shape, spotlight and redact), the canvas shows its outline and handles (resize, bend and corner radius) only while the pointer hovers the mark or a handle, and a press adjusts it only from a handle showing; anywhere else it draws anew. Pen and highlight never show them, so close strokes always start new marks, and a counter has none. ShotCore's `EditorTool.showsHandles(of:hoveredAt:tolerance:)` and `pressedHandle(of:at:hoveredAt:tolerance:)` decide this from `EditorCanvasView.hoverPoint`, where the last `mouseMoved` left the pointer, not where it's pressed, so a quick move and press onto a handle that never showed still draws. A press that draws clears the hover, and so does the pointer leaving. The tools whose `editsSelection` is true always show handles: select, and text and note, whose press picks existing text or a note.
- Undo is snapshot-based through ShotCore's generic `UndoStack`, not `NSUndoManager`. Group continuous edits (slider drags, held keys) into one step. View state like zoom is not undoable.
- ⌘Z, ⇧⌘Z and Edit › Undo and Redo go through `EditorUndo`, which both editors' windows take before the Edit menu, so they work wherever focus is. The window's own `NSUndoManager` only holds a text field's typing: a field being typed in undoes that first, and once it has none left, editing ends and the editor undoes. ShotCore's `UndoRoute` decides which, and enables the menu items whenever the Undo button is.
- A text's or note's sizes are `Annotation.textRuns`, a ShotCore `TextRuns` of pixel sizes over UTF-16 code units, as the text field and Core Text count them. It saves `sizeRuns` only when the parts differ, each as a share of `textSize`, which is the largest part. So older documents open as one size, and whatever scales the text, such as the width or `scaled(by:)`, scales every part. `setText` keeps the sizes of the text that stays. `TextLayout` and `NoteLayout` make each line as tall as the largest text in it.
- Both editors type text and notes into `RunsTextField`, which keeps each part's size in an attribute of its own, so a part keeps its size through edits and zooming. The canvas keeps `editingText` and `editingSelection` current from it, and `AnnotationPalette` sizes the part selected, or scales the whole text from the size shown, else its largest part. A size set while typing is an undo step of the field's, so ⌘Z takes it back before the typing. The field stays open when a click moves the keyboard to another field, such as the size box, and takes it back with its selection when the size changes. Paste Style carries no text size, so it leaves the sizes alone.
- Annotation outlines are `CGPath`s, hit-tested by Core Graphics. Filters are `CoreImageEffects`, text is `CoreTextShaper`, and OCR is Vision.
- `EditorModel` keeps view state and talks to the canvas. The undo steps, coalescing and unsaved-changes tracking are ShotCore's `EditHistory`, and what the crop tool applies is decided by `CropEditing`.
- The window's title bar is `EditorTitleBar` in `EditorRootView.swift`: the file name and size, the tool group (`EditorToolGroup`), Undo, the Canvas menu (`CanvasMenu`, a tile when `ViewThatFits` finds no room for its label), Style, Layers, the Share menu, Save and Copy. ShotCore's `EditorToolbarLayout` says which tools have a button and in what order, and `EditorShareAction` holds the Share menu's order and which of its actions save first. `EditorModel.share(_:)` runs them. The selected tool's options are the style bar over the canvas (`StyleBar.swift`), except in crop mode. `StyleBarOverlay` places it with ShotCore's `StyleBarPlacement` beside `EditorModel.styleBarMark`, which the canvas keeps current in view points, and `StyleBarContent` says what it holds. Every option is in the bar: colour rows on the left (`AnnotationPalette.colorRows`), and the width or text size box, a shape's outlines and a text's alignment on the right (`controlRows`). A redaction's and a spotlight's sliders sit in one row. The width steps through `EditorStyle.widths`, and a note's text colour is `Annotation.noteTextColor`, `nil` for black or white to suit the paper. Edit › Reset Style and the bar's context menu reset. `StyleBar` is generic over `StyleBarEditing`, so the video editor shows the same bar for its drawing options.
- Crop mode has the crop bar (`CropBar.swift`) at the canvas's foot in place of the style bar and the hint: Aspect, the size the crop keeps, Reset, Cancel and Crop. ShotCore's `CropBar` places it clear of the zoom control, whose width the foot reports as `EditorModel.canvasFootLeading`, and gives the size, and `EditorModel.cropBarClearance` tells the canvas how much of its bottom the bar covers, so the fitted image and the crop's bottom handles stay above it. While cropping, Copy in the title bar steps down to a secondary button, since Crop is the next step. The canvas draws the crop itself (`drawCrop`), and `CropEditing` decides what applying it changes.
- Along the canvas's foot, `CanvasFoot` in `CanvasControls.swift` holds the zoom control and the hint. ShotCore's `CanvasHint` picks the hint from the tool, the selection and whether text is being typed, and `ZoomControl` gives the percentage and when − and + can step. `StyleBarPlacement` keeps the style bar clear of the foot through `EditorModel.canvasFootHeight`. `CanvasHost` wraps the canvas in `EditorCanvasContainer`, whose backdrop view draws the dotted background and the image's shadow on a layer of its own, so a drag never redraws the blur.
- The window is the title bar over a hairline, then the canvas edge to edge with the open side panel flush against its right. Both panels draw their surface with `sidePanel(width:)` (`Design/SidePanel.swift`). The Layers panel (`Design/LayersPanel.swift`) lists `EditorModel.layerRows`, frontmost first, with `frameRow` pinned above them while there's a crop; ShotCore's `FrameRowDetail` says what the Frame row shows on its right.
- The Style panel (`StylePanel.swift`) sits beside the canvas while `EditorModel.showsStylePanel` is true, and it and the Layers panel take turns (`toggleStylePanel()`, `toggleLayers()`). ShotCore's `StylePanelLayout` says which sections it shows for the target. The screenshot's frame is ShotCore's `CanvasFrame` (padding in pixels and a `CanvasAspect`), which `EditorDocument.canvasRect` applies after the frame crop, so `contentRect`, and with it where the crop can go, never includes it. A gradient or Desktop fill is `EditorDocument.backgroundFill`, drawn by `AnnotationRenderer.drawFill` over `background`, which holds a colour close to it so shadows tint and the JPEG and checkerboard rules work unchanged. The desktop picture itself is `EditorDocument.desktopPicture`, which `DesktopPicture` reads off the main actor and the snapshot leaves out. Use for new captures saves the frame and fill as `CopiedStyle.canvas` only when there is one, and `applyNewCaptureStyle` puts them back. The corners, shadow and border sections are `StyleSection` (`StyleSections.swift`), generic over `StyleEditing` (`StyleEditing.swift`), which the video editor's Inspector shows too.
- A placed image starts with the Soft shadow in the image editor until an image is given another style: `EditorStyle.editorObjectStyle` and `StyleKind.editorDefaultStyle`, which Reset also uses. The video editor keeps `objectStyle(for:scale:)` and `defaultStyle`, so its clips start plain. A placed image with its own crop shows the crop badge, which the canvas draws over the marks while the pointer is over the image or it's selected; ShotCore's `CanvasCropBadge` says when and where, and a click calls `EditorModel.cropImage(_:)`.
